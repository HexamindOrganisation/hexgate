This guide follows one support team. Their agent works, but it will refund any
amount to anyone who asks. They write down the rules they want, find they have
nowhere to keep them, and put them on the Hexgate platform. By the end, **the
same request gets two different answers depending on who is asking.**

## 1. The agent

It has one tool, `refund_order`. Ask it to refund $400 on an order and it does,
whether the person asking is a new support hire or the head of billing. Nothing
in the code knows who is asking, and nothing caps the amount.

Pick the framework you use. **You won't change this file in the rest of the
guide.**

<Tabs>
  <Tab title="LangChain / LangGraph">
    ```python refund_agent.py
    import asyncio
    from langchain_core.tools import tool
    from langchain_openai import ChatOpenAI
    from langgraph.prebuilt import create_react_agent

    @tool
    def refund_order(order_id: str, amount: float, currency: str = "USD") -> str:
        """Issue a refund against an order."""
        return f"Refunded {amount} {currency} on {order_id}"

    TOOLS = [refund_order]
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
    graph = create_react_agent(
        llm,
        TOOLS,
        name="refund_agent",
        prompt="You are a support agent. Use refund_order to issue refunds.",
    )

    REQUEST = {"messages": [{"role": "user", "content": "Refund $400 on order O-42"}]}

    if __name__ == "__main__":
        result = asyncio.run(graph.ainvoke(REQUEST))
        print(result["messages"][-1].content)
    ```
  </Tab>

  <Tab title="Google ADK">
    ```python refund_agent.py
    import asyncio
    from google.adk.agents import Agent
    from google.adk.models.lite_llm import LiteLlm
    from google.adk.runners import Runner
    from google.adk.sessions import InMemorySessionService
    from google.genai import types

    def refund_order(order_id: str, amount: float, currency: str = "USD") -> str:
        """Issue a refund against an order."""
        return f"Refunded {amount} {currency} on {order_id}"

    agent = Agent(
        name="refund_agent",
        model=LiteLlm(model="openai/gpt-4o-mini"),
        instruction="You are a support agent. Use refund_order to issue refunds.",
        tools=[refund_order],
    )

    REQUEST = types.Content(role="user", parts=[types.Part(text="Refund $400 on order O-42")])

    async def main():
        sessions = InMemorySessionService()
        await sessions.create_session(app_name="refunds", user_id="u-1", session_id="s-1")
        runner = Runner(agent=agent, app_name="refunds", session_service=sessions)
        async for event in runner.run_async(user_id="u-1", session_id="s-1", new_message=REQUEST):
            if event.is_final_response():
                print(event.content.parts[0].text)

    if __name__ == "__main__":
        asyncio.run(main())
    ```

## 2. The policy

Front-line support should refund small amounts in dollars. Billing can go
higher and handle euros. Anything else is refused. As YAML, that's a policy with
two roles:

{/* This refund_order policy is copied by hand in README.md, docs/introduction.mdx (a variant with an extra issue_credit tool), docs/quickstart.mdx, docs/snippets/policy-decider.jsx and platform/dashboard/src/components/quickstart/content.ts: keep them in sync. The chapter 4 register and wrap snippets mirror REGISTER and WRAP in content.ts. */}
```yaml policy.yaml
version: 1
roles:
  support:                       # front-line: small USD refunds only
    default_policy: { mode: deny }
    tools:
      refund_order:
        mode: allow
        constraints:
          - args.amount <= 50
          - args.currency == "USD"
  billing:                       # larger refunds, major currencies
    default_policy: { mode: deny }
    tools:
      refund_order:
        mode: allow
        constraints:
          - args.amount <= 500
          - args.currency in ["USD", "EUR"]
```

<PolicyDecider />

You can check the file on your laptop with the CLI. `hexgate policy test`
evaluates a policy offline: no model, no API keys.

```bash
pip install hexgate

hexgate policy test policy.yaml --role support \
    --tool refund_order --args '{"amount": 400, "currency": "USD"}'
# ✗ DENY · support → refund_order({"amount": 400, "currency": "USD"})
#   reason: Policy on "refund_order" denied: constraint failed — args.amount <= 50

hexgate policy test policy.yaml --role billing \
    --tool refund_order --args '{"amount": 400, "currency": "USD"}'
# ✓ ALLOW · billing → refund_order({"amount": 400, "currency": "USD"})
```

The limits live in the policy, **outside the model**, so a confused or
prompt-injected agent can't raise its own cap.

## 3. The missing piece

The rules are right, but they sit in a file next to your code. **A YAML file
doesn't enforce anything.** Before you can trust it in production, a few
questions need answers:

- How does the running agent load this file and check every tool call against it?
- Where does the file live, so the agent in production and the one on your laptop use the same version?
- Who may change a limit, and does every change need a redeploy?
- When a refund is refused, where do you see who asked, with which role and arguments, and why?

> *"I wish I had a registry for this YAML: one place that holds each agent's
> policy, serves it to the agent, and records every decision."*

## 4. The Hexgate platform

The Hexgate platform is that registry. **Your agent keeps its code. The platform
keeps its policy.** The Hexgate SDK sits between the two: it wraps your agent,
fetches the policy from the platform, checks each tool call before it runs, and
reports the decision back.

  <Step title="Mint an API key">
    Open **API keys** and click **Mint new API key**. Copy it straight away: it is

    ```bash .env

    OPENAI_API_KEY=sk-...
    ```

  <Step title="Register and wrap your agent">
    First, **register** the agent so the platform knows its tools. On first

    `refund_agent.py` stays as it is.

    <Tabs>
      <Tab title="LangChain / LangGraph">
        A compiled graph hides its tools, so name them:

        ```bash
        hexgate register --agent refund_agent:graph \
            --tools refund_agent:TOOLS --model gpt-4o-mini
        ```

        ```python guarded_agent.py
        import asyncio
        from dotenv import load_dotenv
        from hexgate.runtime import HexgateContext
        from hexgate.adapters.langchain import wrap_langchain_agent

        load_dotenv()
        from refund_agent import graph, TOOLS, REQUEST

        agent = wrap_langchain_agent(agent=graph, tools=TOOLS)  # reads HEXGATE_API_KEY

        async def refund_as(role: str):
            result = await agent.ainvoke(
                REQUEST,
                hexgate_context=HexgateContext(user_id=f"{role}-agent-1", user_roles=[role]),
            )
            print(f"[{role}]", result["messages"][-1].content)

        async def main():
            # One event loop for both runs: the model clients cache their HTTP
            # connections, which a second asyncio.run would find on a closed loop.
            await refund_as("support")
            await refund_as("billing")

        asyncio.run(main())
        ```

        ```python guarded_agent.py

        from dotenv import load_dotenv
        from google.adk.sessions import InMemorySessionService
        from hexgate.runtime import HexgateContext
        from hexgate.adapters.google import HexgateRunner

        load_dotenv()
        ```

  <Step title="Put your policy on the platform">
    Open **Policies**, select `refund_agent`, and replace the starter policy with
    the YAML from [chapter 2](#2-the-policy). Save it. The platform signs it and
    serves it to the agent from then on, so the file no longer ships with your
    code.

    <Note>
      Re-registering the agent later updates its tool list but keeps your policy edits.
    </Note>
  </Step>

  <Step title="Try it with two different roles">
    Run the script from step 3. It sends the same request, "Refund $400 on order
    O-42", once as `support` and once as `billing`.

    ```bash
    python guarded_agent.py
    ```

    ```text Output (the model's wording will vary)
    [support] I can't issue this refund: $400 is above the $50 limit for your role.
              Please pass it to the billing team.
    [billing] Done. I refunded 400.0 USD on order O-42.
    ```

    Under `support`, `refund_order` never runs. Hexgate returns a
    `[policy_denied]` message as the tool's answer, and the model explains it to
    the user. Under `billing`, the call is within the limits and goes through.
    Both decisions are now in the **Audit** log:

    | Agent | User | Role | Tool call | Decision | Reason |
    |---|---|---|---|---|---|
    | `refund_agent` | `support-agent-1` | `support` | `refund_order(amount=400, currency="USD")` | ✗ **deny** | `args.amount <= 50` failed |
    | `refund_agent` | `billing-agent-1` | `billing` | `refund_order(amount=400, currency="USD")` | ✓ **allow** | all constraints passed |

    **Now change a rule without touching code.** On the Policies page, raise the
    support limit to `args.amount <= 500` and save. Run the script again: the
    support request goes through, because the SDK picked up the new signed policy
    at the start of the run.

      To chat with the agent in the browser and pick a role from a menu, start it
      with [`hexgate serve`](/cli/serve) and open the **Playground**.
    </Tip>

<Accordion title="Prefer to stay local, with no platform?" icon="laptop-code">
  The same policy file can gate an agent in-process. `enforce_policy` loads the
  YAML, and the per-call `HexgateContext` picks the role. There's no registry,
  no live edits and no shared audit log, which is exactly the gap chapter 3
  describes, but it's the fastest inner loop while you author a policy.

  ```python support_demo.py
  import asyncio
  from hexgate import agent_tool, create_agent, enforce_policy, stream_agent, HexgateContext


  @agent_tool(name="refund_order")
  async def refund_order(order_id: str, amount: float, currency: str = "USD") -> str:
      """Issue a refund against an order."""
      return f"Refunded {amount} {currency} on {order_id}"

  agent, handler = create_agent(
      model="openai:gpt-5.4",
      tools=[refund_order],
      system_prompt="You are a support agent. Use refund_order to issue refunds.",
  )
  agent = enforce_policy(agent, "policy.yaml")

  async def refund_as(role: str):
      print(f"\n[{role}]")
      async with HexgateContext(user_id="u-1", user_roles=[role]):
          async for event in stream_agent(agent, handler, "Refund $400 on order O-42"):
              ...  # render events however you like

  async def main():
      # One event loop for both runs, as in the platform scripts above.
      await refund_as("support")   # refund_order blocked → model sees [policy_denied]
      await refund_as("billing")   # refund_order allowed → the refund runs

  asyncio.run(main())
  ```

  See [Which path do I pick?](/two-paths) for when to use the local loop and when
  to use the platform.
</Accordion>
